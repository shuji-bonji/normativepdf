# ADR-0004: 往復（read → write → read）を段階 1 の受入にする。ただし単独では受入にしない

- 状態: **Accepted**
- 日付: 2026-08-13
- 決定者: shuji

## 背景

段階 1（シリアライザ）の受入を何で測るか。ROADMAP の Phase 2 は最終的に
「実署名検体で `verify_signatures` VALID 維持」を掲げるが、これは増分更新まで
できて初めて回る。その手前で、書いたものが正しいことをどう測るか。

素直な案は往復である。`parse(bytes) → serialize → parse(bytes')` を回し、
2 つの結果が一致すれば書けている、とする。コーパス 2907 検体がそのまま
受入試験になるので、規模も申し分ない。

## 決定

**往復を受入に使う。ただし単独では受入にしない。**

### 1. 往復が証明すること・しないこと

往復が言えるのは「**この parser が読み戻せる形で書いた**」だけである。
両側が同じ parser を共有しているので、**読みの誤りと書きの誤りが打ち消し合う**。

> 例: 名前オブジェクトのバイト列を Latin-1 で読み、Latin-1 で書き戻せば往復は
> 一致する。しかし条文（R-7.3.5-13）は UTF-8 と解釈すべきと言っており、
> 他の実装は別のバイト列を読む。往復は緑のまま、出力は間違っている。

これは「相手が読む形で測る」を怠ったときの典型で、この family では
繰り返し踏んでいる誤りである。したがって:

### 2. 受入は二面で取る

| 面 | 何を測るか | 手段 |
|---|---|---|
| **自己一貫性** | 自分が書いたものを自分が同じ値として読み戻せる | 往復・コーパス 2907 件 |
| **他者可読性** | **自分以外の実装が読める** | `qpdf --check` / poppler `pdfinfo`（DESIGN §4.3・GUARDS T-2） |

**どちらか一方が緑でも受入としない。** 自己一貫性だけなら上記の打ち消しが
残り、他者可読性だけなら値が保たれた保証がない。

### 3. 「一致」の定義

比較はバイト列ではなく **COS グラフ**で行う。バイト一致は目的ではない
（再シリアライズなので当然ずれる。決定論的出力 = DESIGN §4.1 は「同じ入力から
同じ出力」であって「入力と同じ出力」ではない）。

一致とは、元の相互参照表にある**全オブジェクト番号**について、
`getObject()` の結果が構造的に等しいこと。等しさの規則:

- `integer` / `real` は **kind ごと区別する**（R-7.3.3-6 が区別を要求している以上、
  比較でも畳まない）
- `string` は **bytes で比較し、`form`（literal / hex）も比較する**
  （型が form を持つ理由が往復忠実性そのものだから）
- `name` は値で比較する
- `stream` は **`raw` バイト列**と辞書で比較する（復号後ではない。復号は別層で、
  生で比べるほうが強い）
- `ref` は番号と世代で比較する（**解決してから比較しない** — 参照が直接オブジェクトに
  化けても往復としては失敗とみなす）
- `null` を値に持つ辞書エントリは**保存されているものとして比較する**
  （`dictGetRaw` の側。R-7.3.7-7 の等価性は読み出し時の規則であって、
  書き手が勝手に落としてよい根拠ではない）

### 4. 意図的な差分は 3 つだけ。それ以外は失敗

差分を「想定内」と呼べるのは、ここに書いてあるものに限る。増やすときは
この ADR を先に更新する。

1. **`/Length` は直接整数に正規化する。** 元が間接参照でも `raw.length` の
   直接整数として書く。理由: 元の `/Length` は嘘かもしれない（parser は
   `endstream` へのフォールバックで実際の範囲を得ている）。嘘を保存すると
   他者可読性の面で落ちる。比較では **`/Length` を解決値で突き合わせ、
   両側とも `raw.length` に等しいことを要求する**（無視はしない）。
2. **相互参照ストリーム（`/Type /XRef`）とオブジェクトストリーム
   （`/Type /ObjStm`）のオブジェクトは再出力しない。** 段階 1 の出力は古典
   xref テーブル + 全オブジェクト非圧縮であり、これらは置き換えられる帳簿だから。
   その番号は free エントリになる。**中身のオブジェクトは通常の間接オブジェクトとして
   全部書く**ので、グラフは保たれる。
3. **trailer からストリーム固有のキーを落とす。** 元が xref ストリームだった
   場合、その辞書は trailer を兼ねている（§7.5.8）。古典 trailer に写すとき
   `/Type` `/W` `/Index` `/Filter` `/DecodeParms` `/Length` は意味を失うので
   落とす。`/Root` `/Info` `/ID` `/Size` `/Encrypt` は運ぶ。

### 5. 測れない検体は「合格」に数えない

- **暗号化文書**（trailer に `/Encrypt`）は復号が未実装なので往復できない。
  **スキップではなく「測定不能」として別に数える。** 緑の分母に入れない
  （GUARDS T-4: skipped-green は空振り）。
- 読めない検体（現在 26 件）はそもそも書けないので対象外。往復の分母は
  「パースできた検体」であり、その数も記録する。

### 6. 記録する数字

`corpus.lock.json` に往復の baseline を持つ。パース率と同じ規律で、
**下回っても上回っても赤**にする。

## なぜバイト一致を目指さないか

入力バイト列の再現は「元のファイルを保存する」ことであって、シリアライザの
仕事ではない。元ファイルは空白の入れ方・辞書キーの順序・圧縮の有無が
書き手ごとに違い、そのすべてを再現するのは**元の書き手を模倣する**という
別の目的になる。ここで要るのは「条文どおりに書く」ことである。

なお増分更新（段階 1 の後半）は話が別で、**元のバイト列は 1 バイトも変えずに
末尾へ追記する**のが要件になる（署名を壊さないため）。そこでは「元と同じ」が
本当に要求される — その受入は ROADMAP のとおり実署名検体で測る。

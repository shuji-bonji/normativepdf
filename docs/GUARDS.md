## 第一部: ライブラリが守るガード

### 中核原則

> **主張と実体を乖離させない。**
> 適合を主張するなら、その要件を満たせないときは書かずに落ちる。

先行実装（pdfnative）と自 writer は、**別々の場所で同じクラスの事故**を起こしました。

| | 事故 |
|---|---|
| pdfnative F-1 | PDF/A-2b を XMP に書きながら base-14 フォントを埋め込まない |
| 自 writer W-2〜4 | CFF(.otf) を `CIDFontType2`+`FontFile2` で埋め込む / サブセットタグなし / `Length1` 欠落 |

どちらも「適合を主張しているが実体が伴わない」。**これを構造的に防ぐのがこのライブラリの存在理由**です。

### G-A: 適合主張はフォント埋め込みを強制する

PDF/A・PDF/UA を主張する出力で、埋め込めないフォント（**base-14 を含む**）が使われる場合:

- 適合宣言を **書かない**、または
- **明示エラーで停止する**

「主張だけ書いて出力する」を許さない。

> PDF/A は標準 14 フォントも含めて全フォントの埋め込みを要求する
>（`ISO 19005-2 6.2.11.4.1-1` → `ISO 32000-1 §9.9`）。
> ビューア内蔵フォントへの依存は長期保存の再現性保証を壊すため。

### G-B: 「やったつもり」になれる操作は、できなければ非ゼロ終了

暗号化・署名・添付・タグ付けなど、**成功したかどうかが出力を見ないと分からない操作**は、
実施できなかった場合に必ず失敗として返す。**無言で機能を落とさない。**

> pdfnative F-2: `--encrypt aes-256 --owner-password ... --user-password ...` が
> **exit 0・stderr 0 バイト・`/Encrypt` キーなし**の平文 PDF を返した。
> help が明記する「PDF/A と排他」も、エラーではなく暗号化を黙って捨てる実装だった。

### G-C: 増分更新の字句を規格準拠に保つ

オブジェクト構文（`obj` / `endobj` 前後の EOL、オブジェクト番号と世代番号の区切り）を
規格の字句規則どおりに書く。

> pdfnative F-3: PDF/A 適合文書に署名したら、**入力になかった違反が増えた**
>（`ISO 19005-2 6.1.9-1`）。増分更新のオブジェクト構文が規則違反。
> 「PDF/A で長期保存しつつ署名する」は電帳法・契約書保管の中核ユースケース。

### G-D: ページ連結時に catalog レベルのメタデータを引き継ぐ

XMP メタデータストリーム・OutputIntent・その他 catalog エントリを、
マージ／抽出／分割で失わない。

> pdfnative F-4: マージで違反 1 → **3 件**。XMP と OutputIntent を引き継がなかった結果、
> DeviceRGB が根拠を失って **375 件**の違反が噴出した。

**ただし「引き継げるか」ではなく「引き継いで嘘にならないか」で判断する。**
準拠宣言つき XMP や `MarkInfo` を無条件に運ぶと、偽の準拠主張になり、
黙って落とすより悪化する（自 writer B-10b の判断）。

### G-E: 文字を落とすときは黙って落とさない

グリフが解決できない文字は、**警告なしに消さない**。

> pdfnative F-5: フォント未登録で日本語・アラビア語が **段落ごと消失**、
> タイ語は `?` に置換。exit 0・stderr 0 バイト・警告なし。
> しかも**同一の「フォント欠如」状況で処理経路が分岐していた**。

## 第二部: 検証ループの手順則（G-1〜G-6）

実装を書く／生成させる際、この順序を崩さない。

### G-1. exit 0 を成功と読まない

生成後に**読み戻して入力と照合**し、要求した機能の実在を**出力側で**確認する。

> 監査では exit 0 のまま失敗した操作が 2 種あった（文字欠落・暗号化不適用）。
> 終了コードは証拠にならない。

### G-2. 宣言と検証をペアで呼び、差分を出す

`identify_conformance`（XMP の宣言）と `validate_conformance`（veraPDF 採点）は**別物**。
必ず両方呼び、食い違いを明示する。

> 監査した 7 検体すべてで両者が食い違った。片方だけでは F-1 を見逃す。

### G-3. veraPDF の実在を先に確認する

native fallback の `compliant: null` は「**検査した部分集合に違反なし**」であって
**適合ではない**。採点前にエンジンを確認し、fallback なら判定を「保留」として扱う。

### G-4. 外部ツールは `--help` を先にダンプし、かつ help を疑う

**stderr の実メッセージを一次情報とする。**

> 監査では 3 ラウンド連続でフラグを外した。うち 1 回は
> **help が「`latin` は許可」と明記しているのに実装が拒否した**（F-6）。
> AI エージェントは help を読んでコマンドを組み立てるため、help が嘘をつくと G-4 自体が無効化される。

### G-5. ステージ依存を宣言し、前段失敗は「スキップ」と記録する

「失敗」ではない。

> `render` が全滅した結果 `sign` が `ENOENT` で連鎖失敗し、
> ログ上「署名も失敗」に見えた。実際は前段の巻き添え。

### G-6. 変換系は「入力を採点 → 操作 → 出力を採点 → 差分」で回す

単発の合否では原因を特定できない。

> F-3（署名）と F-4（マージ）は、**入力と出力の違反数を比較して初めて**
> 「その操作が壊した」と特定できた。出力だけ見ると「元から壊れていた」と区別がつかない。

## 第三部: テストが空振りしないための規律

自 family で繰り返し踏んだもの。

| # | 規律 |
|---|---|
| T-1 | **委譲先が書いた辞書を、一度は自分の目で開く。** veraPDF も既存テストも中身を見ていないことがある |
| T-2 | **自分の書いたものを自分で読み戻すテストは、その層を原理的に検出できない。** 独立実装（`qpdf --check` / `poppler` / veraPDF）で読み戻す |
| T-3 | **フィクスチャ不在と `if` ガードでテストは緑のまま空振りする。** 修正を戻すと落ちることを実測して確認する |
| T-4 | `skipIf` の条件を `beforeAll` のフラグで立てると**全件スキップのまま緑**になる（定義時に評価されるため）。外部バイナリの有無は同期で確認する |

> 実例: 自 writer W-1（`carryXmp` が出力 PDF を破壊）は、
> **pdf-lib で読み戻すテストが緑だった**ため公開版 0.13.0 まで生き延びた。
> `qpdf --check` を足したら exit 2 で即座に落ちた。

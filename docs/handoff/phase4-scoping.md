# Phase 4 着手前調査 — 条文・受入・スコープの実測（2026-08-22）

- 対象リポジトリ: `normativepdf`
- 位置づけ: [`../ROADMAP.md`](../ROADMAP.md) Phase 4「PDF 2.0 の実体」の着手前チェック。
  **実装はしていない。** ここにあるのは実測 3 つと、そこから立つ決裁事項 1 つである

## 実測 1: 条文のブロッカーは存在しない

Phase 4 は「ISO TS の入手判断が前提」と引き継がれてきたが、**実測すると前提はすでに
解消されていた**。TS 32003 / 32004 / 32005 は 3 冊とも pdf-spec-mcp のコーパスに
sponsored 版（PDF Association 経由の無償配布）で入っており、`list_specs` の id
`ts32003` / `ts32004` / `ts32005` で今すぐ条文が引ける。購入判断は不要。

## 実測 2: 3 冊の Scope（§1 の条文から）

| TS | Scope（§1 実文の要約） | 何の話か |
|---|---|---|
| 32003:2023 | Encrypt 辞書に AES-GCM を追加する拡張 | **暗号化**の拡張そのもの |
| 32004:2024 | "integrity protection to the **encrypted** PDF document"（Encrypt 辞書 + trailer の AuthCode・CMS の MAC トークン） | **暗号化文書限定**の完全性保護 |
| 32005:2023 | タグ付き PDF の PDF 1.7 / 2.0 名前空間の包含規則 | **構造ツリー** = Phase 5（UA-2 / WTPDF）の前提 |

## 実測 3: 受入「veraPDF flavour 4 COMPLIANT」は既に充足している

Phase 4 の受入条件は writer 経由で**既に測られて通っている**: pdf-writer-mcp 0.20.x
（= Phase 3 完了後・生成は normativepdf）のリリース実測が **PDF/A-4 109/109 COMPLIANT**
（writer CHANGELOG・リリースごとの適合レポート `docs/CONFORMANCE.md`）。

この実測は**暗号化もタグも無しで**到達している。つまり TS 3 冊はどれも flavour 4 受入の
前提ではない — 32003/32004 は暗号化を実装するときの条文、32005 は Phase 5 の条文である。
（19005-4 の条文はコーパス外 = T2 なので、条文側からの裏取りは購入後。ここでの根拠は
veraPDF の実測のみ、と明記しておく。）

## 決裁事項: Phase 4 の再定義（未決・shuji さんの判断待ち）

受入は充足済み・中身（TS 3 冊）は受入と噛み合っていない、という状態が実測で確定した。
選択肢:

- **A. 暗号化 Phase として再定義** — 読み側の復号（§7.6。corpus の encrypted 検体は
  parse で名指しエラー 2 件・roundtrip not-measurable 5 件 = 実測needs が既にある）と、
  書き側の AES-GCM（32003）+ MAC（32004）。verify は自前復号（decryptor.ts）を既に
  持っており、共有するかは別判断
- **B. Phase 4 を受入充足で閉じ、暗号化を新 Phase として別起票**（推奨）— 受入は
  実測で閉じ、暗号化は「encrypted 検体が読めない」という実需要から要求駆動で起こす。
  32005 は Phase 5 に送る（もともとそちらの前提）
- **C. 現状維持** — TS 実装を Phase 4 のまま積む。受入と中身の不一致が残る

推奨 B の理由: このリポジトリの流儀（回復パースも「実の壊れ検体で要求が立った分のみ」）
と同じ形になる。暗号化は面が大きく、「Phase 4 だから」ではなく「この 5 検体を読める化する」
から始める方が、受入をまた実測で書ける。

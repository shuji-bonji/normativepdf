## 分かったこと

1. **コーパスに無い壊れ方は、コーパスの A/B では一生測れない。** 36,834 件の文字列に孤立したサロゲートは 1 件も無かった。差 0 件は「既存の入力で答えが変わらない」ことを示すだけで、この変更の振る舞い自体は受入テストの 2 件でしか示せていない。
2. **コーパスの取得は、codeload の tarball が 403 で塞がっていた。** `npm run corpus:fetch` の veraPDF-corpus は `codeload.github.com` の tarball を取るが、作業環境では 403 だった。同じ commit を `git fetch --depth 1 origin <sha>` で取ると通り、件数（2,907）はロックと一致した。
3. **仕様が決めていないことは、初版起こしで「決めた跡が無い」として見える。** §7.9.2.2.1 は UTF-16BE・UTF-8 の定義を Unicode Standard に委ね、形の壊れたバイト列の読み方を書いていない。3 つの壊れ方のうち 2 つにはコードのコメントや標準の既定という跡があり、残りの 1 つには無かった。
